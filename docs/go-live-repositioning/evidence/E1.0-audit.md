## 4. Plan decisions for E1 (no founder input needed; listed for review)

1. **Old offer values leave `siteConfig`.** E1.1 moves `pricing`, `auditPriceRange`, `diagnosticUrl`, `systems`, `impactPhases`, `subline` into one module, `src/lib/legacyOffer.ts` (every line marked `// removed in E10`), imported by the old pages, `aeoContent.ts` and the old Service JSON-LD. `siteConfig` then matches PRD 6.4 exactly and the old pages keep compiling with their old text, without duplicating numbers in JSX (rule 7).
2. **`markets` switches to UAE / Saudi Arabia in E1.1.** Old pages that interpolate markets (e.g. `pmo-automation-gcc`, the old canonical answers) will read "United Arab Emirates, Saudi Arabia" on staging until E8/E10 replace them. Organization/Service `areaServed` becomes AE/SA, which is correct.
3. **`routeLive` is introduced in E1.1** (config, all new routes `false`, existing routes `true`), because E1.3's homepage links to pages built in E2–E6. Homepage links to routes that are not live are rendered as plain text (no dead link); E1.4 wires the same map into nav and footer.
4. **The principal block (IN-3, approved)** ships in E1.3 behind a `principalBlock: true` config flag, so E6.2 can reuse it.
5. **Lighthouse for E1's ≥ 90 gate** runs on a local production build plus the Vercel preview where reachable: previews are behind Vercel login, which Lighthouse in this sandbox cannot pass.
6. **Release path:** all E1 PRs target `release/go-live` (founder decision); production does not change until E10.4.
